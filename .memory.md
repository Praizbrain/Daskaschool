  the old one.

## 2026-08-03 — Clerk tried, then reverted to Supabase Auth

Wired up Clerk (`@clerk/tanstack-react-start`) for auth: `ClerkProvider` in `__root.tsx`,
`clerkMiddleware()` in `start.ts`, custom sign-in flow in `index.tsx` using Clerk's "Signal API"
(`useSignIn()` returning `{ signIn, errors, fetchStatus }` — a 2026 breaking redesign most

**Reverted entirely** after hitting `ClerkRuntimeError: Failed to load Clerk JS
(failed_to_load_clerk_js)` → root cause was `ERR_NAME_NOT_RESOLVED` on Clerk's per-app
`*.clerk.accounts.dev` subdomain — a DNS-level block on the developer's network, same class of
issue previously hit with Context7 CLI (only fixable there with a system-wide VPN). Since the
app's real users (school owner, bursar) can't be expected to troubleshoot networking or run a
VPN to log in, this was judged an unacceptable risk. Switched to Supabase Auth for everything —
one backend, one dependency, no third-party auth domain. All Clerk code, package, and env vars
removed from the repo. **Do not reintroduce Clerk** without confirming this network issue is
independently fixed first — see `context/library-docs.md` for the full note.
