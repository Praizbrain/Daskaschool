# .memory

A running, dated log of what actually happened in this project, session by session — not the
plan (that's `context/progress-tracker.md`), but the real history: what was tried, what broke,
what got reverted, and exactly what state things are in right now.

**Any AI agent starting a session on this repo should read this file first, in addition to
`AGENTS.md` and `context/progress-tracker.md`.** This file answers "where did we actually stop"
— the tracker answers "what's the plan."

## How This File Gets Updated

- After completing any feature, fixing any real bug, or making any decision worth remembering —
  add a new dated entry at the **top** (most recent first).
- Keep entries short and factual: what was done, what state it left things in, what's next.
  Not a transcript — a summary a future agent can act on in 30 seconds of reading.
- Never delete old entries — this is an append-only history. If something in an old entry
  becomes outdated (e.g. "using Clerk" later reverted), the newer entry corrects it; don't edit
  the old one.
- If a session ends mid-task (something half-done, blocked, or waiting on Praise), say so
  explicitly in the entry — "STOPPED HERE: waiting on X" is more useful than silence.

## 2026-08-03 — Clerk tried, then reverted to Supabase Auth

Wired up Clerk (`@clerk/tanstack-react-start`) for auth: `ClerkProvider` in `__root.tsx`,
`clerkMiddleware()` in `start.ts`, custom sign-in flow in `index.tsx` using Clerk's "Signal API"
(`useSignIn()` returning `{ signIn, errors, fetchStatus }` — a 2026 breaking redesign most
tutorials/training data don't reflect; the legacy `{ isLoaded, signIn, setActive }` shape is
NOT what this SDK version uses). Configured Clerk dashboard: Restricted mode on, session token
customized to include `public_metadata` claim, two users created with `role` set.

**Reverted entirely** after hitting `ClerkRuntimeError: Failed to load Clerk JS
(failed_to_load_clerk_js)` → root cause was `ERR_NAME_NOT_RESOLVED` on Clerk's per-app
`*.clerk.accounts.dev` subdomain — a DNS-level block on the developer's network, same class of
issue previously hit with Context7 CLI (only fixable there with a system-wide VPN). Since the
app's real users (school owner, bursar) can't be expected to troubleshoot networking or run a
VPN to log in, this was judged an unacceptable risk. Switched to Supabase Auth for everything —
one backend, one dependency, no third-party auth domain. All Clerk code, package, and env vars
removed from the repo. **Do not reintroduce Clerk** without confirming this network issue is
independently fixed first — see `context/library-docs.md` for the full note.
